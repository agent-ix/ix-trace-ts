## Summary

Ticket: none. This repository has no Linear ticket for PR 15, so these findings are not posted to a tracker; this SR file is the only record. PR 15, head `c449bad`, scoped to `git diff origin/main...HEAD`. The diff is documentation only: README.md, a docs-figures figure definition and four generated SVGs. No production code, tests or spec files changed, so gap-analysis and spec-review do not apply. There are no `.tsx` files, so review-react does not apply.

Evidence gathered:

- A scratch project installed the published `@agent-ix/ix-trace-ts@0.1.0` and `vitest@4.1.12` from registry.npmjs.org with no user npm config.
- The README test snippet, copied verbatim with the README's `vitest.config.ts`, fails with `ReferenceError: it is not defined`. The run exits 1, and `junit.xml` holds `tests="0"` (FND-001). With `import { it } from "vitest"` added, `QUIRE_TRACE_EMIT=1 npx vitest run` writes exactly the `<testcase ... file="parser.test.ts" ...>` with `<property name="trace" value="FR-001-AC-1"/>` shown in the README. Without the variable, the reporter writes vitest's plain JUnit output with no trace property.
- `import type { TraceReporterOptions } from "@agent-ix/ix-trace-ts/vitest"` fails with TS2614. `import type { Implementing } from "@agent-ix/ix-trace-ts"` fails with TS2724. Neither type is exported from `src/vitest.ts`, `src/index.ts` or the published `.d.ts` files (FND-002, FND-003).
- The `implementing()` snippet fails under vitest with no tsconfig (`SyntaxError: Invalid or unexpected token`) and passes with `"experimentalDecorators": true`. The README's decorator note is correct.
- `render.py docs/images/figures.py --check`, run from the installed docs-figures skill (dev-tools 0.2.0), exits 0 and leaves the tree unchanged. Each `<img alt>` equals its figure's `aria-label` and `<title>` verbatim.
- The docs-style grep check has no hits. `prettier --check README.md docs/` is clean.
- Hygiene: the diff adds no private-repo names, research, roadmap, registry text or spec ids. It removes the old `quoin FR-120` / `quire-rs FR-080` lines. The repo is public. agent-ix/.github holds CLA.md and CONTRIBUTING.md, so the Contributing link resolves. `CONTENT_RIGHTS.md` and `LICENSE` exist.

Examined: README.md (every section), docs/images/figures.py, the four SVGs, against src/index.ts, src/vitest.ts, src/trace.ts, src/implementing.ts, src/reporter.ts and package.json.

## Verdict

Not mergeable as is, because of two medium findings in the facts the README states. FND-001 is a documented example that does not run as written. FND-002 is a Reference export that does not exist. Both are one-line README fixes. The rest is correct and matches the package: the two entries and their exports, the `QUIRE_TRACE_EMIT` exact-`1` behaviour, `quireTraceIds`, the optional `^4.1.2` peer range, the experimentalDecorators note, the JUnit property output, the id-shape rule and the `outputFile` default. The structure follows docs-style: lede, hero, Getting started, Usage, Reference, Building and testing, Contributing, License. Alt text equals the figure labels. The figures read the env var, meta key, exports, peer range and export names from the repository, and `--check` is clean. The raw.githubusercontent.com image URLs point to files on this branch under docs/images and will resolve on main after merge. The Contributing section points to the org defaults without requiring CLA.md or CONTRIBUTING.md back. No ceremony was added.
